  (The other L1 probes pass against real host paths: `/home`, `/root`, `/var`,
  `/etc/shadow`, `/etc/ssh`, `$HOME/.ssh`, `$HOME/.aws` — all exist on the host.)
- **L14 R5** (1 weak): the control-socket pid-namespace check (R5) is covered by
  unit tests only; no end-to-end test can place the socket inside the sandbox
  without a test hook (P16).
- **L20** (1 weak): `run.sh` stdin is not a tty; rerun with a terminal for the
  `--tty` terminal-refusal check.

**Note on hostname isolation:** the `sethostname` call in `init.rs` is
best-effort (some containers block it via seccomp even in a new UTS ns). The
hostname is cosmetic (the UTS ns is already unshared; it is not a security
boundary). A WARN line is logged by init when it fails. Hostname isolation
(UTS ns separation) is only verifiable on the host — in the build sandbox
`sethostname` fails but the session still starts; on the host it succeeds and
the hostname inside the sandbox is `hisn`.
