What the 5ea2fc2 log shows for the new tests (read from the log, not assumed):
L14c 1 PASS; L17b 2 PASS (`--prune` removes a stale dir; a dir without
`supervisor.pid` is not pruned); L33 4 PASS; L34 1 PASS; L35 1 PASS. Total
passes 184 = the 175 of the 0.2.0 run + these 9. The one skip is L12
(needs write access to `/etc`) and the one weak is L14 R5 (unit coverage only,
P16); both lines are in the log.

L17b checks added after the 5ea2fc2 run, **not yet run on a host**: (a) a
symlink to a canary directory and file planted inside a stale session dir (also
one in a subdirectory) must not be followed by `hisn ls --prune` (canary kept,
stale dir gone); (b) `hisn run --session-id X` over a stale dir for X must
start, and the old `supervisor.pid` and a marker planted in the old dir must be
gone. Until a host log shows their lines, these two are covered by unit tests
only. `tests/leak/MANIFEST` lists them as `L17b: <text>` entries, so a run that
prints no such line fails.

Causes of the two failed runs (fixed in `5543e7e` and `f298ca5`):

* L34: `scrub_argv` writes `/proc/self/mem`. `5543e7e` moved it before
  `PR_SET_DUMPABLE=0`, but it still ran after `landlock::apply`, and Landlock
  has no write rule for `/proc`, so the open failed with EACCES and the scrub
  silently did nothing. `f298ca5` runs it before Landlock. Unit tests:
  `landlock::tests::proc_self_mem_is_not_writable_after_apply` and
  `init::tests::scrub_argv_overwrites_cmdline`. The L34 assertion ignores NUL
  padding and fails on any other content.
* Manifest: `run.sh` records ids in `OUTPUT_LOG` as the bare test name
  (`L1 stat ...`), without the `PASS  ` prefix, so the regex that expected the
  prefix matched nothing. `f298ca5` matches the bare name.
* L35: `--detach` and a command are mutually exclusive (`a1d238b`); fixed in
  `5543e7e`, PASS since.

### The `Getötet` line

The f298ca5 log contained one bash job-control line,
`run.sh: line 125: <pid> Killed ... "$HISN" run --policy ... loop`, after the
L17b `PASS` lines. It is the command line of `start_session`, so a session
supervisor killed with SIGKILL: the deliberate kill in L17b, which was not
reaped. The edit in 5ea2fc2 adds `wait ... 2>/dev/null` after the kill. The
5ea2fc2 host log has no such line (checked with `grep -c 'Killed\|Getötet'`:
0), which confirms the explanation and the fix. The two new L17b checks use the
same kill-then-wait pattern.
