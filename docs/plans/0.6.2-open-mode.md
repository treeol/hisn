### Block 3 — every `listen` is executed by the supervisor

**3a. Supervisor-execute non-INET listen**

- In `handle_notif` listen path (`src/notif.rs:1444-1453`): for the
  non-INET branch, when `SockNs::Sandbox`, replace `FLAG_CONTINUE` with a
  supervisor `listen()` call on the dup reference — the same pattern
  already used for INET listen (lines 1436-1439).
- `Host` and `Unknown` stay refused (already correct).
- Invariant: the supervisor performs `listen` on its own reference for
  every address family. The kernel never executes a continued `listen`
  from a sandboxed task.

**3b. Update verdict table**

- `verdict_table` (`src/notif.rs:2755`): the `Listen` entry's answer
  changes from the current split description to `SupervisorExecuted`.
  The rationale text updates: the supervisor executes `listen` on its
  own reference for every address family after namespace classification;
  `Host` and `Unknown` are refused.
- `KernelContinued` remains only for `ConnectUnix` and `BindUnix`.

**3c. Update verdict_table_continue_only_where_covered test**

- The test at `src/notif.rs:4110` already asserts `KernelContinued` only
  for `ConnectUnix | BindUnix`. No change needed to the test's assertions.
  The `Listen` entry stays in the "never `KernelContinued`" list — verify
  it still passes.

**3d. Parity cases: AF_UNIX listener**

- Add to `tests/leak/net_cases.sh`: a parity case that creates an
  AF_UNIX path listener inside an open session, connects a client, and
  exchanges data. Same for AF_UNIX abstract namespace.
- The client must connect and exchange data bidirectionally, proving
  the supervisor-executed `listen` produces a working listener.
- Test: run `net_cases.sh` on .213; new cases pass.

**3e. Measure peer credentials on .213**

- On .213, run a test that reads `SO_PEERCRED` (pid, uid, gid) from the
  client side of an AF_UNIX connection whose listener was
  supervisor-executed. Compare with the same measurement on a v0.6.1
  build on the same machine.
- Document the measured difference in the ADR amendment and release
  notes.
- If uid or gid differ, stop and report before going on.
