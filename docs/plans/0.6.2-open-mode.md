  listen gap — the table is documentation, not coupled to the dispatch
  code.
- **Listen handling** (`src/notif.rs:1429-1456`):
  - INET listen (`d_is_inet` true): `Sandbox` → supervisor executes
    `listen()` on dup; `Host | Unknown` → refuse.
  - Non-INET listen (`d_is_inet` false): `Sandbox` → `FLAG_CONTINUE`;
    `Host | Unknown` → refuse.

    the two branches will make it dead — clippy `-D warnings` will fail
    if it is not removed.

  kept host socket to **succeed** ("want success", line 696). But the
  code refuses it (`SockNs::Host => refuse_implicit(EACCES)`, line 1441).
  This test is wrong — the code correctly refuses because a
  supervisor-namespace socket's listen would auto-bind a port in the
  supervisor namespace. `net_cases.sh:475` expects `listen=ok`. Both must
  be corrected to expect `EACCES`.
- **`handle_implicit_call` doc comment** (`src/notif.rs:1421-1428`):
  says "AF_UNIX listen records the caller's credentials (SO_PEERCRED),

### Block 2 specification (from Mashūra round 1 finding 3)

**Function name:** `verdict_for(class: NotifClass) -> Verdict`
where `NotifClass` is an enum covering the call classes: syscall
(connect/bind/listen), address family (INET/AF_UNIX/other), and socket
side (sandbox/host/unknown). The verdict function is the single
authority for whether a call is continued or refused.

**Gate check location:** `tests/release-gate.sh` step 0c (new step),
after the existing force-continue check. It greps for `FLAG_CONTINUE`
write sites in `src/notif.rs` that are NOT inside the verdict function
and NOT behind `#[cfg(feature = "force-continue")]`. Pattern:
`grep -n 'FLAG_CONTINUE' src/notif.rs | grep -v 'fn verdict_for' |
grep -v 'cfg(feature = "force-continue")'` — any match fails the gate.

**Force-continue site handling:** sites 1374 and 1664 are behind
`#[cfg(feature = "force-continue")]` and are excluded from the gate
check (they do not exist in release builds). Site 1515 is unreachable
in production and kept as defensive code; it is excluded from the gate
check with a comment explaining why. Sites 1481 and 1910 are the
production continue sites that must route through `verdict_for`.
