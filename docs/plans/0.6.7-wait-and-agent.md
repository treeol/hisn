# hisn 0.6.7: journal wait and caller-provided SSH agent socket

Base: tag `v0.6.5` (d57b423), branch `work/0.6.7`. The version number 0.6.6 is
skipped on purpose; CHANGELOG and release notes say so in one line
("0.6.6 was not released; 0.6.7 follows 0.6.5").

Where this plan and the code disagree, the code wins; differences are listed
in section 1.

## 0. Intent and workflow class

Intent: **implement** (multi-file, public API, security-relevant signing
surface, concurrency in the wait loop). Tier: **3** — 1 pre-implementation
(this plan, Mashūra round 1) + 1 post-implementation (round 2 over the full
diff). Hard cap: 2 rounds per gate.

Confirm gate: auto-proceed conditions hold — scope follows directly from the
task text, changes are local/in-repo/reversible, no push/tag/deploy, no
destructive or production action, no ambiguity that changes files/behaviour.
Shell commands and commits still pass their normal per-command gates.
Unrelated dirty files in the worktree (`SHA256SUMS`,
`hisn-x86_64-linux-gnu`, `wakil-next`) are never staged.

## 2. Scope A — `hisn journal --wait`

**Design (D-A1).** New flag `--wait [SECS]` on `hisn journal`, requiring
`--after-wseq N` (clap `requires`). The wait loop runs **before** filters
and rendering, on the unfiltered cursor result:

- Loop: `cursor_read(dir, N)` on the unfiltered run.
  - `Reset` / `Gap` → return their existing exit codes 3/4 immediately, the
    first time they appear **and** when discovered after a wake (a reset
    journal or a hole is not something waiting fixes).
  - `Records`: check (a) **session end** first (see below), then (b)
    whether the **filtered** query (`journal::query` with the same
    `--session`/filters as the non-wait path, main.rs:1100-1116) is
    non-empty. Non-empty → advance the internal cursor to the last returned
    wseq, print like the non-wait path, exit 0. Empty (e.g. only foreign
    records arrived) → keep waiting; the caller advances its own `N` from
    the next `--info`/printed record either way — the wait does not hand a
    cursor back, it only guarantees the printed run is filtered-non-empty.
  - No new records → wait for a wakeup, then re-read.
- Session end (only with `--session`, R8 decided): scan the unfiltered
  `Records` run **before** filters/rendering for a `session/stop` whose
  session id equals the `--session` id (incarnation-aware: the stop must
  follow a `session/start` for the same id after the wait began — reuse the
  `record_groups` incarnation logic, journal.rs:1513-1560, so a stop from an
  earlier incarnation with `wseq <= N` cannot stop this wait; a stop with
  `wseq > N` always counts). Precedence in the same batch: filtered records
  present → print + exit 0; no filtered records but stop present → exit **7**
  `E_WAIT_SESSION_ENDED` (stdout empty). `--wait` without `--session` never
  session-exits (documented). Documented limitation (B3): a SIGKILLed
  supervisor that wrote no stop record, or a failed stop append (rule 5 is
  best-effort), is **not** detected — the wait then ends only by timeout.
  That limitation is stated in help and docs, not hidden.
- Timeout (`SECS` given): exit **6** `E_WAIT_TIMEOUT` (documented next to
  3/4 in cli.rs help, `docs/EXTERNAL-CALLERS.md`, and `journal_cmd`'s doc
  comment; verified: 3/4/125 are the only codes on the journal path today,
  5 is unused, 6 is the first free small integer — round-1 review asked why
  5 is skipped; answer: keep the 3,4,6,7 table with 5 left unused/reserved
  and say so in the doc, so a later code does not collide with a gap a
  reader might assume is meaningful). `--wait 0` means: one immediate read,
  then timeout. Negative/fractional values are rejected by clap's `u64`
  type. Timeout/session-end race: records win (checked first each pass).
- No `SECS`: wait indefinitely (bounded only by the documented session-end
  limitation above).
- **Wake mechanism (R1 corrected):** two watches — a **file watch on the
  current `journal.jsonl`** (`IN_MODIFY`, for appends) plus a **dir watch**
  (`IN_MOVED_TO | IN_CREATE | IN_MODIFY`, for rotation/create). A dir watch
  alone does not deliver append `IN_MODIFY` for an existing child file on
  all kernels; the file watch is the append path. Rotation: on
  `IN_MOVED_TO`/`IN_IGNORED`, re-open and re-watch the new current file.
  Watches are armed **before** the first `cursor_read`, and pending inotify
  events are drained **before** each re-read, so an append between read and
  block cannot be lost. Events are filtered by name to `journal.jsonl` /
  `journal.<n>.jsonl` only — `journal.lock` and `journal.idx.*` (written by
  the reader's own `cursor_read`) must not wake the waiter (self-trigger
  spin). `IN_Q_OVERFLOW`, watch failure, or inotify unavailable →
  degrade to 1 s polling; correctness never depends on inotify. `--wait`
  when the workspace dir does not exist yet: watch arming fails with
  `ENOENT` → poll fallback, retry arming each tick until the dir appears.
  Latency, stated honestly: typically immediate on append (file watch);
  worst case ≤ 1 s (poll) + read cost; a unit test asserts wake latency
  well below 1 s with the poll timeout raised, so a dead inotify path
  cannot hide behind the poll forever. The 1 s poll is also the
  self-terminating guard for the session-end limitation above (a stop
  record written by any means is picked up within 1 s even if inotify is
  dead).
- **No lock while waiting:** `cursor_read` takes the shared lock briefly to
  pin fds (F4); the wait loop holds nothing between passes. `--wait` never
  opens a control socket or takes a session lock.

**Tests (Block A):**

- Unit (in `src/journal.rs` or a new `src/journal/wait.rs`): wake/timeout
  logic against a temp dir — append wakes the wait (latency assertion);
  timeout fires with the documented outcome; rotation during wait still
  returns the record; session-end outcome (stop with no matching records →
  7; matching record + stop in one batch → 0 with records); prior-incarnation
  stop with `wseq <= N` does not stop the wait; inotify-unavailable still
  works via the poll fallback (injection seam: a `WaitBackend` trait or a
  flag that disables watching, so the test does not depend on the host
  having inotify); filtered-empty foreign appends keep the wait alive.
- Leak/e2e (`tests/leak/`): wait-then-append (a second process appends after
  the waiter starts), wait across a forced rotation (small `rotate_after`
  via `Journal::with_rotate_after` in a unit test, or a big generated
  journal e2e), timeout exit code, session stop while waiting (real
  session) → exit 7.

## 3. Scope B — caller-provided SSH agent socket

**Design (D-B1 — interface decision).** Add `socket: Option<String>` to
`SshConfig` (profile.rs:543) **and** a `--ssh-agent-socket PATH` flag on
`run`. (Round-1 reviewer 1 recommended CLI-only, arguing a profile key is a
machine-specific host path with a profile-controlled connect target. The
plan keeps both, because the `[ssh]` table exists precisely for this proxy —
`agent`/`keys` are already there (F14), and capabilities/`profile validate`
already gate profiles — but flags the dissent as an open point in §9; if the
user wants the smaller surface, dropping the profile key is a one-line plan
change, no other design depends on it.) Both feed the same prepare path: when set, the upstream is that path
instead of `SSH_AUTH_SOCK`, validated by the existing `check_host_agent`
(is-a-socket check). Default off: neither set → today's behaviour for the
upstream choice (upstream = `SSH_AUTH_SOCK`, required when `agent = true`).
The profile key exists because the `[ssh]` table already carries
`agent`/`keys` for this exact proxy (F14: additive, backward compatible);
the CLI flag exists because callers of `run` otherwise cannot hand a socket
without a profile edit. CLI wins if both set (documented, with a test).
The value is consumed **at prepare time, host-side** (the same place
`SSH_AUTH_SOCK` is read today, supervisor.rs:4329); it is not a control
`Request` field, does not travel on the documented wire, and does not bump
`PROTOCOL_REVISION` or touch the v0.6.3 fixture. Where the flag reaches the
supervisor (spawn args / internal `SessionControlArgs` — the exact struct
is named in Block 2) is internal plumbing, not wire protocol; the compat
script proves the external wire is unchanged. Interaction rules: `--ssh-agent-socket`
without `[ssh] agent = true` is an error (the flag does not silently enable
the proxy); `socket` set with `agent = false` is the same error at validate
time; the path must be absolute; a non-socket path fails with the existing
`check_host_agent` error, whose text is fixed to name the path actually
checked (not always `SSH_AUTH_SOCK`). **The resolved upstream path is
carried in `PreparedEnv`** (supervisor.rs:4362) and read once at
`start_control` — the spawn must not re-read `SSH_AUTH_SOCK` from the
environment (`unwrap_or_default` at supervisor.rs:4747 goes away for this
path), so a caller socket can never silently fall back to the default
agent. Test: flag and `SSH_AUTH_SOCK` set to two different agents → the
proxy reaches the flag's agent.

**Design (D-B2 — attribution, proved).** `do_forward` for the proxy socket is
a **bind mount, not a relay** (`prepare_tree` → `open_tree` clone, then
`move_mount` in the helper — supervisor.rs:1249-1332, grant.rs:275-295,
415-474): the `/run/ssh-agent.sock` the sandbox sees is the same socket
inode the proxy bound. So `SO_PEERCRED` on the accepted proxy connection
names the **actual in-sandbox client process**, and the ancestry walk
below starts from it. If a future change ever relays instead of mounting,
attribution silently collapses to the relay — guard with a comment at the
`do_forward_inner` call site and a leak test that a real in-sandbox client's
sign is attributed to its seat.

- New lookup returning **`(seat, role, exec_id)`**: extend the existing
  `exec_seats` map (supervisor.rs:363, `BTreeMap<i32, Option<String>>`,
  pid → seat) so the resolved top pid yields the exec id and seat **and**
  the seat's role from the seat store. `resolve_seat`'s walk
  (notif.rs:676) is reused unchanged (same `/proc` rules, same no-cache
  rule — notif.rs:675); only its lookup result grows. One per-sign walk, no
  cache (round-1 review agrees this is fine for signing rates; 64 small
  reads against a signing operation).
- Main-command identification: the walk must distinguish **main command**
  (the session's init tree, pid 1 at the sandbox depth — walk to the top pid
  and compare against the session init pid) from **orphan/reparented**
  (walk reaches init without matching an exec top pid, or ends above the
  sandbox depth, or errors). Decision table, deny by default:
  - attributed exec with role owner/member → sign allowed;
  - attributed exec with role **observer → refused** (`result: "refused"`,
    `SSH_AGENT_FAILURE`);
  - main command (positive match to the session init tree) → sign allowed
    as owner (this is the `hisn run -- git push` case);
  - orphan, reparented-to-init, over-deep (>64), nested-pidns, unreadable
    `/proc`, or any walk error → **refused** (`result: "refused"`,
    `attribution: "unattributed"`), never silently allowed. An observer
    cannot bypass by double-forking: that only reaches the refused bucket.
  - Residual limitation, stated in docs: the walk is racy against pid
    reuse (a client that exits and whose pid is recycled between accept and
    walk could be misattributed). Mitigation: do the walk at `accept()`
    (smallest window; `SO_PEERCRED` is fixed at connect time) and re-check
    the role per `SIGN_REQUEST`. A `pidfd` (`SO_PEERPIDFD`, kernel ≥ 6.5) is
    the stronger fix — deferred, listed as an open point; not required for
    0.6.7.
- `data.exec_id` is the matched exec's id (`e-<n>`) or `null` for the main
  command / unattributed. `data.seat` is the seat name or `null` (network
  records use `null`, journal.rs:539 — **not** the string `"unattributed"`,
  which would collide with a seat of that name and with `--seat` matching;
  the explicit marker is a separate boolean `attributed: false`).

**Design (D-B3 — role rule).** New `Op::Sign` in the role table
(authz.rs:140): `allows(Member, Sign) = true`, `allows(Observer, Sign) =
false` (owner always true). The check is the **pure role predicate**
`authz::allows(role, Op::Sign)` called with the role the supervisor
resolved for the attributed client — against a supervisor-supplied,
immutable seat→role snapshot. **Forbidden explicitly:** the proxy must not
construct a `ClientRecord` or an `Authorized` token, must not present a
credential, and must not widen any constructor's visibility to make it
possible. `authorize()` stays the only producer of `Authorized`; the proxy
never holds one. A unit test pins that no control `Request` maps to
`Op::Sign` (`Op::of` has no arm producing it; the exhaustive match in
`Op::of` / `Op::name` either gains a `Sign` arm returning a name that no
`Request` reaches, or `Sign` lives outside `Op` — decide in Block 2; the
invariant is: no wire request can produce `Op::Sign`). `Op` is not
serialized anywhere near the compat fixture (verified: the fixture carries
`Request` lines only), so this cannot break compat_063. Refusals are
journaled (`result: "refused"`) with the seat recorded. **The env path
(`SSH_AUTH_SOCK`, no flag) goes through the same `handle_client` and the
same check** — the plan's old "byte for byte" claim is narrowed: the
upstream choice is unchanged by default, but observer refusal and the new
`ssh/sign` records apply to both paths. Stated explicitly in release
notes (this reverses the old allowlist-only behaviour for observers on
both paths).

**Design (D-B4 — signing journal).** Each SIGN_REQUEST handled by the proxy
writes **one** journal record, kind `ssh/sign`, through the bounded
`NetQueue` (journal.rs:211-383) — **not** a synchronous `append` in the
client worker: a synchronous append can wait up to the 1 s flock budget per
sign and an attacker can flood refused/malformed signs and rotate the
journal, evicting older audit history under retention. Reuse the
`clone_for_engine` handle (journal.rs:428) and the `NetQueue` discipline:
`NET_RECORDS_PER_SEC = 50` individually, the rest counted into a summary
record. The summary record for signs is `ssh/sign-summary` (counts by
result + dropped) — `network/summary` is the precedent
(journal.rs:331-353); `NetCounts` gains sign arms, or a parallel counter
set. A summary record is written once per affected second, never per sign.
`NetQueue` is generic over the record kinds it already carries
(`NetMsg::Record(kind, data)`), so `ssh/sign` flows through it with no new
queue machinery. That the sign path adds at most queue latency, never a
journal write, to a sign: documented.

- `data.fingerprint`: `SSH_FINGERPRINT` form (`SHA256:…`, already computed
  by `ssh_fingerprint`) or `null` when the envelope was unparseable;
- `data.seat`: the attributed seat or `null`; `data.attributed: bool`;
- `data.exec_id`: `e-<n>` or `null`;
- `data.result`: `ok` / `refused` / `error`. `ok` requires the host reply
  byte to be the sign-response type (14, `SSH_AGENT_SIGN_RESPONSE`); a host
  `SSH_AGENT_FAILURE` (5) maps to `"refused"`, a malformed/short reply to
  `"error"`. The response is currently passed through unparsed
  (ssh_agent.rs:325-338) — Block 2 adds the type check without changing
  what's forwarded (the client still receives the host's exact reply
  bytes). Host connect/read/write failure → `"error"`. Connect is made
  **lazy** (on the first forwarded message, not at accept — ssh_agent.rs:251)
  so a down host agent still produces one `ssh/sign` record with
  `result: "error"` per sign attempt instead of an invisible bare FAILURE.
- **Never** the data being signed, never the signature, never the key blob.
- Every outcome is journaled: ok, allowlist-refused, role-refused,
  malformed envelope, host connect failure, host FAILURE reply. Refused
  non-sign message types (add/remove/lock/…) keep today's `tracing`-only
  logging (D-B5, out of scope) — but the summary/`summary_for` has an
  `ssh/sign` arm so readable `hisn journal` output never says
  "unrecognized ssh/sign" (add to `summary_for`, journal.rs:1663; the
  `/refused` catch-all arm at 1721 covers only kinds ending in `/refused`).
- Journal write failures never fail the sign (rule 5, journal.rs:9-16):
  `append` errors are counted, the sign proceeds. The `client` field of
  the record is `None` (a proxy client is not a control client; using
  `JournalClient::seat` would falsely claim `label_source: "seat"` =
  credential-authenticated — round-1 finding, adopted).

**Design (D-B5 — add/remove).** Unchanged: only 11/13 forwarded; add/remove
still refused with `SSH_AGENT_FAILURE` (F8). `REQUEST_IDENTITIES` (11) stays
ungated by role (observers may list allowlisted fingerprints — read-only,
and the existing behaviour); only SIGN (13) is gated. The new journal
records cover sign requests only; refused non-sign message types keep
today's `tracing`-only logging (documented, out of scope).

## 8. Data model (journal records)

- `ssh/sign`: `{fingerprint: "SHA256:…" | null, seat: "<name>" | null,
  attributed: bool, exec_id: "<id>" | null, result: "ok" | "refused" |
  "error"}`; `ssh/sign-summary`: counts by result + `dropped`. No new `v`
  version (additive `data` keys, F11).
- `--wait` adds no records. Exit codes: 6 `E_WAIT_TIMEOUT`, 7
  `E_WAIT_SESSION_ENDED` (both documented beside 3/4; 5 left unused and
  documented as such).

## 9. Mashūra round 1 — blocking findings and disposition

Three reviewers. Blocking findings (all folded into §§2–4 above):

1. **B1/B2 (wait semantics).** Exit 7 was unreachable as drafted (a stop
   record is itself a record after the cursor); the wake condition was
   undefined once filters applied; `Reset`/`Gap` bullets contradicted each
   other. Fixed: session-end is checked on the **unfiltered** run before
   filters; the wake condition is **filtered**-non-empty; `Reset`/`Gap`
   exit 3/4 immediately, always. Acceptance cases pinned in §2.
2. **B3 (session-end can hang).** Stop record `wseq <= N`, SIGKILLed
   supervisor, failed stop append: all undetectable from the journal alone.
   Documented as a stated limitation (§2); the wait ends by timeout in
   those cases. No liveness probe on the session dir (a probe would tie
   `--wait` to supervisor liveness, which the task's journal-only design
   avoids).
3. **B4 (peer attribution unproven; role bypass).** Verified in code:
   `do_forward` is a bind mount (`open_tree` + `move_mount`), so
   `SO_PEERCRED` names the real client (§3 D-B2). Unattributed policy is
   now a deny-by-default decision table (orphans/reparented/errors refused;
   main command positively identified, not "not an exec"). `exec_id`+role
   via an extended `exec_seats` lookup (§3). Pid-reuse: walk at `accept()`,
   re-check role per sign; pidfd deferred as open point.
4. **B5 (upstream resolved twice).** `PreparedEnv` carries the resolved
   path; `unwrap_or_default` re-read goes away (§3 D-B1), with a
   two-different-agents test.
5. **B6 (unbounded `ssh/sign`).** Synchronous append replaced by the
   bounded `NetQueue` + `ssh/sign-summary` (§3 D-B4), with a flood test.
6. **R1 (inotify).** Corrected to file-watch-for-append + dir-watch-for-
   rotation + 1 s poll; arm-before-first-read, drain-before-re-read,
   name filtering (no self-wake on `journal.lock`/`journal.idx.*`), latency
   test (§2). One reviewer (fable) recalled dir watches do fire for child
   `IN_MODIFY`; the two others recalled they do not. The design does not
   depend on which is true (file watch covers appends either way).
7. **R4 (authorize boundary).** Pure `authz::allows(role, Op::Sign)`
   predicate; forging `ClientRecord`/`Authorized` explicitly forbidden; no
   `JournalClient::seat` (§3 D-B3/D-B4). Unit test: no `Request` maps to
   `Op::Sign`.
8. **R6/R7 (C4/C3 shapes).** C4: parse stops, post-parse collects (§4).
   C3: finalise under the `exec_table` lock, not a re-read (§4). Both
   reviewers' alternative shapes (re-read after `wait_pumps`) rejected as
   window-narrowing only.

Reviewer claim corrections adopted: "always twice" → `cursor_read` second
scan only when the first is not clean (F1); `seat: null` + `attributed`
instead of `"unattributed"` (D-B2); `ssh/sign` arm in `summary_for`
(D-B4); SIGN_RESPONSE 14 type check (D-B4); lazy connect (D-B4);
`check_host_agent` error text names the actual path (D-B1).

## 10. Open points (non-blocking, carried forward)

1. **P1 — B interface dissent.** Reviewer 1 recommends CLI-only (a profile
   key is a machine-specific host path). This plan keeps both (D-B1).
   Dropping the profile key is trivial if the user prefers the smaller
   surface.
2. **P2 — Identity-list gating.** Type 11 stays ungated for observers
   (D-B5); if identity listing should also be role-gated, that's a
   follow-up.
3. **P3 — pidfd hardening.** `SO_PEERPIDFD`/`pidfd_open` across the walk
   (kernel ≥ 6.5) would close the pid-reuse window; deferred, walk-at-accept
   is the 0.6.7 mitigation.
4. **P4 — ADR updates.** ADR 0011 (agent proxy) and ADR 0021 (seats) need
   a short amendment for the role gate on the proxy and the journal
   records; and `cli.rs` "no follow mode" help text must be updated when
   `--wait` lands (§5 docs block).
5. **P5 — `--wait` cursor hand-back.** The wait prints the filtered run
   but does not return the next cursor; callers advance from `--info` or
   the last printed wseq. A future `hisn journal --wait --json` shape with
   an explicit cursor field is deferred.
6. **P6 — non-sign refusal journaling.** Refused non-sign message types
   (add/remove/…) stay `tracing`-only; journaling them is deferred (would
   need the same flood cap discussion as B6).
7. **P7 — exit code 5.** Left unused/reserved and documented; if a future
   release wants it, it can be claimed without renumbering 6/7.
8. **P8 — test isolation on `.213`** (R10, unchanged): leak/e2e steps start
   real sessions with user namespaces; the host-verify script uses its own
   prefix and temp state dirs (0.6.5 pattern, F17).
