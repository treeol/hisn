# hisn v0.4.2

0.4.2 hardens the profile surface and closes audit findings from a review of 0.4.1. Profile loading now rejects values that previously panicked or hung at run time, readiness probes cannot outlive their timeout, and `session.json` updates are race-free.

## Highlights

- Profiles with `grace` or readiness `timeout` above 86400 s are now rejected at load.
- NUL bytes in exec strings and `ready.tcp` are now rejected at load.
- An exec whose client disconnects before `started` is now cancelled.
- A `ready.command` probe is bounded by `ready.timeout` and a hung probe is killed with its process group.
- `session.json` is written under `session.json.lock`.

## Changed

- **Profile validation.** Profiles with `stop.grace` or readiness `timeout` above 86400 s, NUL bytes in exec strings, or `ready.tcp` are now rejected at load instead of panicking at run time. `ready.tcp` is rejected with `E_NOT_SUPPORTED` (not implemented); it is still parsed so the error is clear rather than an unknown-field error. Deadline computations use checked arithmetic.
- **Readiness probes are bounded.** A `ready.command` probe is bounded by the overall `ready.timeout`. A probe that hangs is killed with its process group at the deadline and startup fails at about `timeout`. A slow probe that completes within `timeout` succeeds.
- **Cancelled execs are killed.** An exec whose client disconnects before `started` is now cancelled (TERM then KILL) instead of being left running.
- **`session.json` is written under `session.json.lock`.** Read-modify-write updates (`set_state`, `record_member`, `touch_lease`) now take an exclusive `flock` on `session.json.lock` in the session dir, so the supervisor and `hisn stop` cannot lose each other's updates. Temp file names are unique per call. `flock` retries on `EINTR`.

## Fixed

- **Host-service stop race.** The stop loop's `reaped` flag means SIGKILL is never sent to an already-reaped pid. `EINTR` retries the wait and does not end the grace. A `ready.tcp` spec no longer falls back to "assume ready".
- **Dead code removed.** Removed `session::mode_of`, `ServiceHandle.name`, `init::raw_fd`, a stale `#[allow(too_many_arguments)]` on `run_supervisor_inner`, and the unused `_socket` parameter of `check_readiness`.
- **L33 test fix.** Leak test L33 cross-exec steps now use `--no-tty`, matching neighbouring steps.
- **SSH agent SHA-256.** The hand-rolled SHA-256 in `ssh_agent` is replaced with the `sha2` crate (already a dependency). Fingerprint output is unchanged.

## Hardening

- Both fork sites (host-service start and readiness probe) build every `CString` and pointer vector before `fork`; between `fork` and `exec` there is no allocation and no panic path. Inherited fds are closed in the child.
- `ready.tcp` fails closed: a spec naming only `tcp` is not ready, so the fallback "no readiness check: assume ready" cannot be reached by it.
- Docs no longer advertise `ready.tcp` for `[[host_services]]`.

## Compatibility

- The JSON schema (`schemas/hisn-policy.v1.json`, generated from `Policy`) is unchanged: it does not contain profile `ReadinessSpec`, so no change was needed.
- Profiles that loaded in 0.4.1 and are well-formed load unchanged. Profiles in the newly-rejected set (grace/timeout above 86400 s, NUL bytes in exec strings, `ready.tcp`) fail at load with a validation error instead of panicking or hanging at run time.
- No new dependencies. `sha2` was already in `Cargo.toml`.

Known issue carried forward: `ttyname()` inside an attach still fails. The fix needs a protocol change and a host to verify it. See CHANGELOG and DESIGN section 20.1.

## Verified

- `cargo fmt --check` passes.
- `cargo clippy --all-targets -- -D warnings` passes.
- `cargo test --lib`: 404 passed, 2 failed. The 2 failures are the known sandbox pair (`init::tests::scrub_argv_overwrites_cmdline`, `landlock::tests::proc_self_mem_is_not_writable_after_apply`) that pass on a host.
- Host verification (rubin): unit tests 406/0, leak suite 307/0/9/1, readiness checks pass. B2 exec-cancel check: a disconnected exec is killed and `execs` is empty. Readiness-hang check: a hung probe fails startup at about `timeout` with exit 125 and no leftover process. Slow-probe check: a 3 s probe succeeds under `timeout = 10`. Overflow and NUL profiles are rejected at `hisn profile validate` with exit 125.
