# hisn v0.4.3

0.4.3 adds no features. It locks in the 0.4.2 fixes with regression tests, adds a release gate, fixes smaller audit findings, and restructures session startup so the coming egress proxy, cgroup v2 limits and multi-seat work can be added safely.

## Highlights

- Host services run in their own process group with stdin `/dev/null`; stopping a session stops a host service's child processes too.
- Startup fails immediately when a host service exits before readiness completes, naming the service and its exit status.
- A service shows `starting` in `ls --json` until readiness passes.
- The SSH agent proxy now has 30 s read and write timeouts on the host socket.
- New release gate: `make release-gate`.
- New leak cases L76–L81.

## Changed

- **Host services run in their own process group.** A host service is now a process-group leader (`setpgid(0, 0)` in the child, `setpgid(pid, pid)` in the parent) and its stdin is `/dev/null` (it is outside the terminal's foreground group; stdout and stderr go there too, so a chatty service cannot corrupt the terminal). Stopping a session signals the whole group: `killpg` first, then `kill` only on `ESRCH` (a duplicate non-KILL signal would otherwise hit the leader twice); KILL is idempotent so it always double-sends. On reap the leader is observed first and the group is then SIGKILLed, so a TERM-ignoring child does not survive. A host service that previously read interactive terminal input will now read EOF; terminal signals (Ctrl-C) no longer reach it directly — it is stopped by the supervisor's own stop path instead.
- **Startup fails at once when a host service exits before readiness completes.** The readiness wait checks the service pid before and after every probe (a `WNOHANG` waitpid that reaps on first sight); on death it returns the exit status and startup fails with `host_service <name>: exited with status <n> before readiness completed`. The reaped pid is removed from the cleanup guard's kill set, so it is never signalled again.
- **A service shows `starting` in `ls --json` until readiness passes.** `state` is `"starting"` from spawn until readiness passes, then `"ready"`; `"exited"` when the monitor is gone. `ServiceState.exit` stays `null` for in-sandbox services (by design: the pid is in the sandbox pid namespace, so the supervisor cannot `waitpid` it; only the monitor reaps it). Field names and types are unchanged — a client that trusted `"ready"` immediately after start will now see `"starting"` for the duration of readiness (bounded by `ready.timeout`, default 15 s).
- **SSH agent proxy timeouts.** The host agent socket now has a 30 s read timeout alongside the existing 30 s write timeout. Trade-off: a sign request waiting on a human (touch/confirm) longer than 30 s fails.
- **Release gate.** `scripts/release-gate.sh` and `make release-gate` run the full gate in order, stopping at the first failure: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `make check`, `make test`, the leak suite through a pipe (stdout genuinely not a TTY), and the leak suite on a pseudo-terminal via `script` when present (otherwise a SKIP line stating why, and a summary that says `skipped-no-script` rather than claiming `ok`). Without `HISN_TEST_ROOTFS`/`HISN_BIG_TESTS` set it prints a warning that the rootfs and big-import cases will skip. It installs nothing and touches no session it did not start.

## Fixed

- `recv_with_fd` returns `EMSGSIZE` when a control message is truncated (`MSG_TRUNC|MSG_CTRUNC`), dropping any fd that arrived first — the same treatment `recv_with_fds` gives via its `truncated` flag.
- `rootfs.rs`: both `dup` sites (`ensure_dir_tracked`, `ensure_existing_dir`) now go through `dup_owned`, which returns the OS error when `dup` fails instead of wrapping `-1`.
- `stdio_to_dev_null`: the `dup2` error path now closes the opened fd only when it is above 2 (both paths now guard the close with `n > 2`).
- SSH agent proxy: a `ClientGuard` (created inside the worker thread) decrements the client counter on every exit path including a panic unwind; the manual `fetch_sub` after `handle_client` is gone.
- `sessionmeta::rewrite` removes the exact temp name before `create_new`, so a leftover temp from a crash plus pid reuse cannot fail the write; every `rewrite` caller holds the `flock` first.
- Release-gate honesty: the leak suite is run through a pipe (`| cat`), because `2>&1` alone is not a pipe, and the summary reports `leak-suite-pty=skipped-no-script` when `script` is absent instead of `ok`.
- Leak tests L77/L78: the helper socket path now comes from `argv[1]` (passed in the profile's `exec` line, the L37 pattern) instead of `os.environ`, which never reached the host service; L78 now also asserts the socket exists and accepts a connection.
- Round-review fixes in the refactor: the ExecTable insert no longer panics on a failed status dup inside the `admit`/`lease_lock` closure; the two `check_risk_ack` messages for `[[forward]]` and `[docker]` are byte-identical across the two profile-load sites; namespace fds are dropped after the helpers fork instead of being held for the whole session; dead-service detection re-checks the pid after the probe; the cleanup guard uses `killpg` + `kill` and removes reaped pids from its kill set; `stop_and_reap` always SIGKILLs the group after the leader is gone in the same iteration.

## Hardening

- **Session startup is restructured with no intended behaviour change.** `run_session` (590 lines, 19 parameters) is now 152 lines behind one `SessionStart` struct, split into named phases; a single cleanup guard covers every early exit. Service code moved into a new `src/services.rs` module (`ServiceHandle`, in-sandbox and host-service start, readiness waits, `stop_and_reap`). Host and in-sandbox services share one `stop_and_reap` path (the merged `reap` keeps the `EINTR`-retrying form). Profiles are loaded once (`Profile::overrides` and `check_risk_ack`). The five exec maps are folded into one `ExecTable`. PTY/reply helpers are shared between the supervisor and attach paths.
- Leak case **L76** — exec cancel on early disconnect: the token process is gone within ~5 s, `ls --json` shows execs=0 and clients=0, and the `idle_timeout = 3s` session stops itself.
- Leak case **L77** — hung readiness probe: start fails in 1–6 s with exit 125, the output names the readiness probe, and no probe process remains.
- Leak case **L78** — slow readiness probe: the session starts, startup took about 3 s (the probe was actually waited for), and the host service socket exists and accepts a connection.
- Leak case **L79** — load-time rejections: five sub-cases (grace and timeout above 86400 s, NUL in `host_services.exec`, NUL in `ready.command`, `ready.tcp`), each asserting exit 125, the offending key named, and no session dir created.
- Leak case **L80** — host-service stop kills the whole process group: a service that spawns a child ignoring TERM; after the session ends neither process exists.
- Leak case **L81** — readiness fails when the host service is already dead: exit 125 in at most 6 s against a 30 s timeout, with the literal `host_service ...: exited with status 7 before readiness completed` message.

## Compatibility

- The control-socket protocol, the `ls --json` fields, the `supervisor.pid` format, the exit codes and the profile schema are unchanged.
- Two user-visible changes: host services no longer share the supervisor's terminal stdin (stdin is `/dev/null`), and stopping a session now stops a host service's child processes too. Startup also fails earlier (but with a clearer error) when a host service exits before readiness.

Known issue carried forward: `ttyname()` inside an attach still fails. The fix needs a protocol change and a host to verify it. See CHANGELOG and DESIGN section 20.1.
