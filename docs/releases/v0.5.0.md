# hisn v0.5.0

0.5.0 adds the workspace journal: the supervisor records what a session did, not
only the audit trail, and `hisn journal` reads it back in one compact line per
event.

## Highlights

- **Workspace journal.** A session records grants, exec requests and results,
  exec exits, notes/markers, session start/stop, and a git-change report.
- **`hisn journal`.** Compact lines for execs (argv, exit code, duration),
  notes, grants/revokes, and git changes, with `--json`, `--last N`, `--seat`,
  `--kind` and `--since` filters. `--session ID-or-NAME` resolves the
  workspace from any directory, even after the session has ended.
- **`hisn note`.** A verbatim note/marker is journaled through the control
  socket; it is never parsed or executed.
- **Workspaces.** A session's workspace is the one derived from its canonical
  cwd, or `--workspace NAME`; by default every session in one directory shares
  one journal, while explicit workspaces can split or merge across
  directories by name.
- **Git-change report.** Start/stop snapshots of `.git/hooks` and `.git/config`
  are journaled as one short diff. Report only: nothing is blocked or reverted.
- **Protocol revision 2.** `client.protocol_version` / `protocol_revision`
  gates the new `note` op and its optional fields; absent means revision 1.
- **Additive `ls --json` fields.** `hisn_version`, `protocol_revision`,
  `workspace`, `journal`, and `journal_failures`.

## What is recorded

The workspace journal (`journal.jsonl`, mode 0600, one JSON object per line,
`$XDG_STATE_HOME/hisn/workspaces/<id>/`) carries `v`, `ts`, a workspace-wide
`wseq`, `session`, `kind`, the journaling client (uid, label, label source and
request id when present), and `data`. The journal is a record, not a replay
mechanism. Its kinds include:

- grant/revoke requests and results, auth refusals, kill/signal requests,
  forwards and lease expiry (the same audit information, journal shape);
- session start and stop;
- notes and markers;
- git-change records (see below).

An exec's journal request record carries the argv — capped at 512 bytes in
total across all elements, whole elements only — with `argv_truncated` and the
original `argv_count`/`argv_bytes` when capped, plus the working directory
when the request carries one. When even the first element does not fit, the
recorded argv is empty and the counts still report the original command. The
journal can contain whatever a command line contains, including secrets: argv
is recorded verbatim, without pattern-based redaction. This is journal-only;
`grants.jsonl` never carries argv.

One `exec/exit` record follows each completed exec (a normal exit, a signal,
a cancelled or a lost run; see "launcher wrapping" below): same `seq` and
request id as its request, the exit code or terminating signal, whether it
was cancelled or lost, and the duration in milliseconds.

`hisn journal` runs on the host, not inside a session, and reads the
journal files directly (rotated files included) — so it shows records from
sessions that have stopped or been pruned. Default output is one compact line
per event; `--json` prints records unchanged, one full record per line.
Readable output is terminal-escaped; `--json` is exact data and is meant for
machine consumption, not pasted to a terminal. Long text is shown on one
line: special characters are escaped, nothing is cut short.
Filters (`--workspace`, `--session`, `--seat`, `--kind`, `--since`) select
events before display. A merged exec line has kind `exec`; in readable mode
`--kind exec` selects the exec family, while `--json` matches raw kinds
exactly. In readable mode `--last N` counts displayed events after merging —
exec groups are retrieved complete from the retained journal — while `--json`
keeps counting raw records.

`hisn journal --session ID-or-NAME` looks up the live `session.json` first,
then persistent session markers (`workspaces/<workspace-id>/sessions/<session-id>`,
mode 0600 in a 0700 directory) across all workspaces, before falling back to
the current-directory workspace. It therefore works from any directory while a
session runs and after it has ended. A reused name resolves to the newest
marker and the chosen session id is reported when ambiguous. An explicit
`--workspace` confines the lookup to that workspace. `hisn note --session S
[--marker] TEXT` (or `-` for stdin) stores a note/marker verbatim, at most
8 KiB.

## Git-change report

At session start and at orderly stop, hisn snapshots `.git/hooks` (name, size,
mode, SHA-256) and `.git/config` (SHA-256 and parsed keys) — plain files only,
bounded, without following symlinks out of `.git` and without invoking git —
and journals one `git-change` record: hooks added/removed/modified and config
keys added/removed/changed, with program-executing keys flagged (`core.hooksPath`,
`core.fsmonitor`, `core.sshCommand`, editor/pager/credential-helper style
keys, `alias.*`, `filter.*`, `diff.*.textconv`, `include.path`,
`includeIf.*`, `url.*.insteadOf`, and the rest of the `DANGEROUS_KEYS` list
in `src/gitreport.rs`). If `.git` is missing or is a file (worktree/submodule)
the record says the report was skipped and why. When nothing changed, the
record is short — cwd,
an explicit `unchanged` marker and hook/config-key counts, no snapshots.
**Report only:** nothing is blocked, reverted or made read-only, and no profile
key is required.

## Compatibility

- A 0.4.3 client works against a 0.5.0 supervisor: six of the eight existing
  control ops — grant (`src/supervisor.rs:862-864`), revoke
  (`src/supervisor.rs:940-955`), list (`src/supervisor.rs:1810-1818`), kill
  (`src/supervisor.rs:1830-1833`), exec (`src/supervisor.rs:1296-1325`) and
  signal (`src/supervisor.rs:1380-1407`) — answer with the same bytes as
  before, and `grants.jsonl` is unchanged (the journal is written in addition,
  never instead). The other two gained purely additive fields: `sessioninfo`
  now also returns the text `workspace` id plus `journal_failures` and
  `journal_bytes` (`src/supervisor.rs:1474-1478`), and `inspect` also
  returns `journal_failures` and `journal_bytes`
  (`src/supervisor.rs:1575-1591`). `sessioninfo` had neither set before 0.5.0
  and `inspect` neither; a strict 0.4.3 parser that rejects unknown response
  fields would see the new keys. `E_VERSION` is only ever answered to a
  request that declares a protocol revision, which a 0.4.3 client never does.
  A real Wakil pinned to hisn 0.4.3 drove a session started by this build
  without problems (verified above).
- The 0.5.0 CLI sends nothing new to a 0.4.3 session: it reads
  `protocol_revision` (absent = revision 1) and so sends neither
  `client.protocol_version` nor the new `note` op, and a refused note against a
  revision-1 session exits 2 rather than sending an unknown op.
- Running 0.4.3 sessions are not affected by installing 0.5.0: a live
  supervisor forks its helpers once at startup and never re-executes its
  binary by path, so replacing the installed file does not reach it.
- `ls --json` gains only additive fields (`hisn_version`, `protocol_revision`,
  `workspace`, `journal`, `journal_failures`); no field is renamed, retyped or
  removed.

## Known limitations

- **0.4.3 `session.json` rewrite.** A 0.4.3 binary that rewrites
  `session.json` (for example `hisn stop`) drops the fields it does not know,
  after which that session is treated as protocol revision 1. (A 0.4.3 reader
  itself is untouched: `session.json` has no `deny_unknown_fields`, so the new
  optional fields are ignored on read.)
- **Command lines.** The journal can contain whatever a command line contains,
  including secrets. It is private to the user (workspace dir 0700, journal
  0600), and workspace state is not mounted into a session by default (L82);
  a session deliberately run with a cwd or grant covering the state home
  would see it.
- **Durability.** Records are synced at session stop and at rotation, not per
  record, so a power failure can lose the tail since the last stop/rotation
  sync.
- **Rotation.** Rotated `journal.<n>.jsonl` files are never deleted
  automatically; they accumulate until workspace state is removed manually.
  Journal queries look back through every retained file once (no fixed total
  history cap); retained history sets the query cost ceiling.
- **Crashes.** A supervisor that dies leaves no stop snapshot for the
  git-change report; the next session takes a fresh start snapshot as its new
  baseline.
- **Launcher wrapping.** A client that wraps its commands in a launcher (as
  Wakil does for background execution) is journaled as the launcher: argv, exit
  code and duration are the launcher's own, not the wrapped command's.

## Verified

- `make release-gate` on rubin: leak suite `350 passed, 0 failed, 9 skipped,
  1 weak`.
- With `HISN_TEST_ROOTFS` and `HISN_BIG_TESTS`: `363 passed, 0 failed,
  5 skipped, 1 weak`.
- A Wakil pinned to hisn 0.4.3 drove a session started by this build (commands,
  exit codes, durations, notes from the 0.5.0 CLI side, session stop and the
  git report all appeared in the journal); `hisn journal --session <id>`
  worked from another directory for a running and for a stopped session.
  `hisn note` against a 0.4.3-started session was refused with exit 2.
- `target/debug/hisn --version` prints `hisn 0.5.0`.

Known issue carried forward: `ttyname()` inside an attach still fails (see
CHANGELOG and DESIGN section 20.1).
