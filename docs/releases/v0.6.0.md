# Release notes — hisn 0.6.0

`network = "open"`: controlled outbound TCP from inside the empty
network namespace, implemented by intercepting `connect()` with seccomp
user notification and letting the supervisor decide each one (ADR 0022,
rollout 0.6.0 — mechanism only, no allowlist).

## What changed

- **New mode `open`.** `network = "open"` (and `--network open`) keeps
  the empty netns as the security boundary exactly like `none` — new
  `CLONE_NEWNET`, loopback up, no route — but adds a controlled exit:
  the supervisor connects on the session's behalf from the host netns
  and injects the socket (`SECCOMP_IOCTL_NOTIF_ADDFD` + `SETFD`).
  `network = "none"` is unchanged and byte-identical to 0.5.1;
  `network = "host"` is unchanged.
- **Interception.** Every outbound `connect()` on a stream socket is
  intercepted by a hand-written BPF filter (`connect` → `USER_NOTIF`,
  everything else → `ALLOW`; foreign-arch kill). Loopback and unix
  connects `CONTINUE`; unknown families, non-stream (UDP/QUIC),
  and private/loopback/link-local/CGNAT/RFC1918/ULA targets are
  refused `EACCES` — also in `open` (`open` is allow-all *public*,
  not allow-all at all). Every notification has a 30 s deadline
  (`ETIMEDOUT`), a bounded 64-worker pool, and queue-full refusal
  (`EACCES`, fail closed, never a hang). Each exec tree installs its
  own listener (`EBUSY` forbids a second in one chain); `hisn exec`
  programs are intercepted too, not just the main command.
- **DNS responder.** In `open`, init binds `127.0.0.1:53` (UDP+TCP)
  before caps drop and hands the fds to the supervisor, which
  forwards queries to the host resolver and answers `SERVFAIL` on
  failure. Sessions get a generated `/etc/resolv.conf`
  (`nameserver 127.0.0.1`) and `/etc/nsswitch.conf`
  (`hosts: files dns`). `none` gets neither.
- **Journal.** Every decision is a `network/connect` record
  (`target`, `verdict`, `reason`, `seat`, `session`, `wseq`) plus
  `network/dns`; records coalesce into `network/summary` and the
  journal keeps at most 4 files. Journal failures are counted, never
  block a verdict.
- **Fail closed.** Startup checks the kernel features by attempting
  them (floor 5.9, naming the feature and its minimum kernel), and
  refuses when Yama `ptrace_scope >= 2` (it breaks the supervisor's
  `process_vm_readv`). The supervisor verifies its netns differs
  from the sandbox's. `seccomp.extra_deny = ["connect"]` /
  `["socket"]` is rejected at validate (an `ERRNO` verdict would
  outrank the interception).

## Known limitations (asserted, not hidden)

- `SOCK_DGRAM` `connect()` is refused `EACCES` (UDP beyond DNS is
  unsupported in 0.6.0; most TCP clients fall back).
- A program that `bind()`s before `connect()` loses its local
  address choice (the socket is recreated in the host netns).
- A program that sets `PR_SET_DUMPABLE=0` after exec and then
  connects gets `EACCES` (the sockaddr cannot be read).
- Non-blocking `connect()` blocks until the supervisor finishes
  (up to the deadline) rather than returning `EINPROGRESS`.
- Host-loopback, RFC1918 and other private targets are refused in
  `open` unless there is no rule for them at all (there are no rules
  in 0.6.0 — private access needs 0.7.0's allowlist).
