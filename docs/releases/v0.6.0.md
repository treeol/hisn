# Release notes — hisn 0.6.0

`network = "open"`: outbound TCP for a session that still lives in an
empty network namespace. Every `connect()` is intercepted with seccomp
user notification; the supervisor decides it, connects from the host
network namespace and puts the connected socket into the program
(ADR 0022). There is no allowlist in this release: `open` allows every
public address. `network = "none"` stays the default.

## What changed

- **New mode `open`** (`session.network = "open"`, `--network open`).
  The sandbox gets its own network namespace with loopback only, like
  `none`. `none` and `host` behave as in 0.5.1.
- **Connect decisions**, in this order:
  1. unix sockets and loopback addresses continue in the sandbox
     (the kernel carries out the original call);
  2. address families other than IPv4, IPv6 and unix are refused
     (`EACCES`);
  3. sockets that are not stream sockets are refused (`EACCES`), so
     there is no UDP out of the sandbox except DNS to the responder;
  4. non-public targets are refused (`EACCES`): private, link-local,
     CGNAT, unique-local, site-local, multicast, unspecified,
     `198.18.0.0/15`, `0/8`, `240/4`, and IPv6 forms that embed such an
     IPv4 address (IPv4-mapped, IPv4-compatible, NAT64 `64:ff9b::/96`,
     6to4, Teredo); the local-use NAT64 prefix `64:ff9b:1::/48` is
     refused as a whole;
  5. everything else is connected by the supervisor and injected
     (`SECCOMP_IOCTL_NOTIF_ADDFD` with `SETFD`, then `NOTIF_SEND`).
  When a queue of 256 notifications is full, a connect is refused at
  once (`EACCES`).
- **Blocking and non-blocking sockets.** The supervisor's own connect
  is always non-blocking; what the program sees depends on its socket:
  - *Blocking socket*: `connect()` returns when the connection is
    established (0) or has failed (the connect's errno). A connect that
    does not complete within 30 s of its notification gets `ETIMEDOUT`;
    the 30 s include any waiting inside the supervisor. Up to 64 such
    connects wait at the same time, further ones queue.
  - *Non-blocking socket* (this includes a socket with a timeout in
    Python, which sets `O_NONBLOCK`): the supervisor injects its
    connecting socket and `connect()` returns `EINPROGRESS` at once.
    The program then sees `POLLOUT` and reads `SO_ERROR` on its own
    descriptor: 0 when connected, the error (for example
    `ECONNREFUSED`) when not. If the supervisor's connect finishes or
    fails immediately, `connect()` returns 0 or that errno instead.
    `EINPROGRESS` is only returned after the socket was injected; if
    the injection fails the answer is `EACCES`. The 30 s deadline does
    not end such a connect: it stays with the kernel's own connect
    timeout, like any non-blocking connect.
  - A second `connect()` on a socket whose connect is pending returns
    `EALREADY`; on a connected socket `EISCONN`; on a socket whose
    connect failed it returns that failure (the pending error, or
    `ECONNABORTED` once `SO_ERROR` was read) and starts no new
    connection.
  - If the supervisor cannot read whether the program's socket is
    non-blocking, the connect is refused (`EACCES`,
    `refuse/flags-unreadable`).
  16 threads read and decide notifications and start the connects; they
  never wait for a connection, so a non-blocking connect is answered
  without waiting for blocking ones that are pending.
- **Every program is covered**: the main command, programs started with
  `hisn exec` and `hisn attach`, and all their threads and children.
- **DNS.** Sessions in `open` get `/etc/resolv.conf` with
  `nameserver 127.0.0.1` and an `/etc/nsswitch.conf` with
  `hosts: files dns`. A responder in the supervisor answers on
  `127.0.0.1:53` (UDP and TCP) by forwarding to the host's resolvers,
  taken from the first of: `[net] nameservers` in the profile,
  `/run/systemd/resolve/resolv.conf`,
  `/run/NetworkManager/no-stub-resolv.conf`, `/etc/resolv.conf`. A
  loopback resolver such as `127.0.0.53` is a valid upstream. If none
  of them names a resolver, the session does not start and the error
  lists the files. An upstream that does not answer within 2 s gives
  `SERVFAIL`.
- **Journal.** `network/connect` records carry `target` (`ip:port`),
  `verdict` (`allow`, `refuse`, `continue`), `reason`, `pid`. `seat`
  is `null` in 0.6.0 (per-connect seat attribution is planned for
  0.7.0). An allowed connect has reason `injected` (the program got a connected
  socket) or `injected-inprogress` (a non-blocking program got the
  connecting socket and `EINPROGRESS`). For the latter the supervisor
  keeps its own descriptor of that socket until the connect has ended,
  at most until the 30 s deadline, and writes one
  `network/connect-result` record: `target`, `result` (`connected`,
  `failed` with `latency_ms` 0 when the connect failed at once, or
  `pending-at-deadline`) and `latency_ms`. It learns the outcome from
  the socket's TCP state and never reads `SO_ERROR`, so the
  error stays for the program to read; the record therefore has no
  errno. Closing the supervisor's descriptor does not close the
  program's. At most 1024 connects are followed this way at a time;
  further ones are injected and answered as usual but get no result
  record and are counted (`tracked_overflow` in `network/summary`).
  `network/dns` records carry `name`, `qtype`, `proto`, `upstream`,
  the real response code in `rcode`, and `verdict`: `ok` for an
  answer, `failed` for a negative answer such as `NXDOMAIN`, `error`
  when no upstream answered (with `error` naming the cause). At most
  50 network records per second are written one by one; the rest are
  counted in a `network/summary` record (`allow`, `refuse`,
  `continue`, `dns`, `result_connected`, `result_other`, `dropped`,
  `tracked_overflow`). A connect never waits for a journal
  write. For a session in `open`, once the workspace journal exceeds
  256 MiB in more than four files, the oldest rotated files are
  deleted after a rotation; other sessions never delete journal files.
- **Refusing to start.** `open` checks at session start that the
  kernel has the needed seccomp operations (by trying them; needs
  kernel 5.9 or newer, plus `pidfd_open` and `pidfd_getfd`), that the
  supervisor is in a different network namespace than the sandbox, and
  that Yama `ptrace_scope` is 0 or 1 (a value of 2 or 3, or a file
  that cannot be read, refuses). `seccomp.extra_deny` containing
  `connect` or `socket` is rejected under `open`.

## Compatibility

- **Protocol revision** is unchanged at 3. `open` adds no new
  control-protocol operations; the wire format and all existing ops
  are byte-identical to 0.5.1. A client pinned to an earlier hisn
  version sees no difference. `net-policy-set` and `net-explain` are
  planned for 0.7.0 (allowlist mode) and are not in this release.
- `network = "host"` is not aliased to `open`; it stays unchanged
  with its deprecation warning. `none` is byte-identical to 0.5.1.

## Known limitations

- **The socket is replaced.** The program's descriptor number is kept,
  but it refers to a new socket. A socket registered with epoll before
  `connect()` receives no events from that registration afterwards,
  and a duplicate of the descriptor made before `connect()` stays
  unconnected. Node (`http`, `fetch`) and Go (`net/http`, `net.Dial`),
  which register the socket after `connect()`, are part of the tests.
- **No `connect-result` record** for a blocking connect (its
  `network/connect` record already has the outcome), for a
  non-blocking connect beyond the 1024 followed at a time, and for
  connects still pending when the session ends.
- **Options set before `connect()`**: the non-blocking flag,
  close-on-exec, `SO_REUSEADDR`, `SO_KEEPALIVE`, `SO_RCVBUF`,
  `SO_SNDBUF` and `TCP_NODELAY` are carried over; all others
  (timeouts, `SO_LINGER`, TOS, keepalive timing, ...) are lost.
- **`bind()` before `connect()`** is lost: the connection leaves from
  an address and port the host chooses.
- **UDP**: `connect()` on a datagram socket to a non-loopback address
  is refused; `sendto()` without connect fails `ENETUNREACH`. QUIC and
  other UDP protocols do not work.
- **No private targets**: there is no way to allow a private or
  host-loopback address in `open`.
- **DNS answers are not filtered**: a name may resolve to a private
  address through the host's resolver; the connect to it is refused.
- **Loopback inside the sandbox is not policed**: any program in the
  session can reach any listener on the session's own loopback.
- **Cost**: about 97 µs per intercepted connect against about 21 µs
  for a direct one on the test machine (see below).
- **Kernels 5.9 to 6.8**: threads are handled through a fallback that
  needs `kcmp`; this path has unit coverage only, it has not been run
  on such a kernel.
- **32-bit programs are killed by the connect filter**: the BPF
  filter checks `seccomp_data.arch` and kills any task whose
  architecture is not the native one (`SECCOMP_RET_KILL_PROCESS`).
  A 32-bit (i686) binary on a 64-bit kernel has a different
  `AUDIT_ARCH` and is killed before it can call `connect()`. Only
  the native architecture (x86_64 or aarch64) is supported.
- **An abandoned non-blocking socket stays alive** in the supervisor
  until the 30 s deadline; the program may close its own descriptor
  while the supervisor's tracked socket is still connecting. The
  supervisor closes its copy when the connect ends or the deadline
  fires, whichever comes first.
- **`connect()` on a connected socket to a private address returns
  `EACCES`**, not `EISCONN`: the supervisor always checks the target
  before answering, so a program that somehow has a connected socket
  and calls `connect()` on it to a private target gets `EACCES`
  (the private-address block runs before the `EISCONN` check).
- **Descriptor reuse race**: another thread of the program that
  closes and reuses the descriptor number while `connect()` is
  suspended gets the socket injected at that number. The supervisor
  injects on the original fd number, so the program's new use of that
  fd receives the connected socket it did not ask for (ADR 0022
  known gap, accepted for 0.6.0).
- **`tcp_info` offsets assume 64-bit**: the completion tracker reads
  `TCP_INFO` with `struct tcp_info`, whose field offsets differ between
  32-bit and 64-bit kernels. Only 64-bit is supported.
- **DoH or custom resolvers** bypass nothing but are not intercepted
  at name level: a program that hardcodes an IP address (e.g.
  `1.1.1.1:53`) instead of using the session's `/etc/resolv.conf`
  still gets its connects intercepted and decided; only DNS *names*
  are handled by the responder. The responder forwards to the host's
  resolvers, which may include a DoH upstream; the interception does
  not see or filter the upstream transport.

## Verified

`7.3.3-300.fc45.x86_64`), Yama `ptrace_scope = 1`, at commit
`4ec88bc`, with `bash scripts/host-verify-network.sh --real`:

  with `hisn rootfs import --from-tar`) and `HISN_BIG_TESTS=1`:
  `468 passed, 0 failed, 5 skipped, 2 weak` (pipe run; pty step

  `github.com`, and the LAN gateway refused;
