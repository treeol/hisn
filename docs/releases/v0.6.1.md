# Release notes — hisn 0.6.1

0.6.1 hardens `network = "open"` (ADR 0022), makes the journal answer
more questions about network records, and removes private host names
from shipped text. `none` (the default) behaves as in 0.6.0 apart from
journal retention.

## Security

`open` is meant to let a program reach only the targets the connect
policy approved. Since 0.6.0 the supervisor hands a socket to the
program before its connect has completed. If that connect failed, the
program kept a socket that lives in the supervisor's network namespace,
not in the sandbox's empty one. In 0.6.0 such a socket could still be
used for a loopback connect, for `bind` and `listen`, and for a
fast-open send, all in the supervisor's namespace. 0.6.1 refuses these
on such a socket (`EACCES`) and gives the loopback/`AF_UNIX` "continue"
verdict only for a socket whose namespace is known and is not the
supervisor's. **Upgrade before running untrusted code in `open`.**

One time-of-check gap is known and not closed in this release: ADR 0022,
section "0.6.1 hardening", "Known gap".

## Fixed

- Journal retention applies to every session, whatever its network mode,
  and each deletion writes a `journal/pruned` record that `hisn journal`
  shows as a readable line.
- `connect()` on an already connected socket returns `EISCONN` for any
  target, private included (0.6.0: `EACCES` for a private one).
- `tcp_info` fields are read by their definition, not by hardcoded
  offsets.
- Shipped text no longer names private hosts or addresses; the release
  gate checks for them case-insensitively.
- `hisn journal --seat NAME` selects network records of that seat.

## Changed

- **Kernel 5.14 for `open`** (`SO_NETNS_COOKIE`; 0.6.0: 5.9). On an older
  kernel `open` refuses to start and names the feature. `none` and
  `host` are unaffected.
- **Journal retention** now applies to every session (once per
  workspace, oldest rotated files first, beyond 256 MiB in more than four
  files). In 0.6.0 only `open` sessions pruned.
- **New record fields and kinds.** `network/connect` carries `notif_id`
  and `pid` and names the `seat` of the exec that caused it, found by
  process ancestry of the calling task (children and threads included;
  the main command, in-sandbox services and processes detached from
  their exec record `null`; DNS records carry no seat).
  `network/connect-result` carries the seat of its connect. New kinds:
  `network/implicit` (a `bind`, `listen` or fast-open send; the target
  names the syscall) and `journal/pruned`.
- **Cost of an intercepted connect: about 151 µs against about 97 µs in
  0.6.0** on the same host (direct connect about 20 µs). The filter now
  also notifies `bind`, `listen` and fast-open sends, and each connect
  resolves its seat from `/proc` and the namespace of its socket. Session
  start did not change: `run --detach` took 12–19 ms in both builds on a
  second test machine.

## Compatibility

- Control protocol revision is unchanged at 3 (`PROTOCOL_REVISION` in
  `src/sessionmeta.rs`); no operation was added or changed.
- A client pinned to 0.6.0 sees no change on the wire. Journal consumers
  that reject unknown fields or record kinds will see the new fields and
  the kinds `network/implicit` and `journal/pruned`.
- `open` on kernels 5.9–5.13 stops working (see Changed).

## Known limitations

All limitations of 0.6.0 that this release does not mention still
apply (`docs/releases/v0.6.0.md`), among them: the socket is replaced at
`connect()`, private targets cannot be allowed, UDP other than DNS does
not work, 32-bit programs are killed by the connect filter. One entry
changes: a `connect()` on a connected socket to a private address now
returns `EISCONN`.

New or sharper in 0.6.1:

- Every `bind` and `listen` in an `open` session now passes through the
  supervisor; when its notification queue is full they fail `EACCES`.
- The descriptor-swap gap named under Security.
- A process that detached from its exec records seat `null`.
