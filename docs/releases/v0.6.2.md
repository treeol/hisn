# Release notes — hisn 0.6.2

0.6.2 makes open-mode enforcement independent of timing. `none` (the
default) behaves as in 0.6.1.

## Security

**What changed.** In 0.6.1, for a call the supervisor left to the
kernel, the check (made on one view of the caller's descriptor and
memory) and the kernel's execution (on its own view, later) were two
separate moments. A program written to exploit that timing could get
a call through that the policy would have refused. 0.6.2 removes
that class of decision:

- A. The supervisor performs `listen`, and `connect`/`bind` with an
  AF_INET/AF_INET6 address, itself on its own `pidfd_getfd` reference
  to the caller's socket, classified by namespace cookie, with its
  own copy of the arguments. The checked object and the acted-on
  object are the same.
- B. Landlock TCP bind/connect rules (no allow rules) are added to
  the sandbox Landlock domain in open mode, for the main command
  chain and exec helpers. The kernel refuses a TCP connect or bind
  by any sandboxed task at execution time, on whatever socket it
  ends up acting on.
- C. Fast-open sends are answered `EOPNOTSUPP` by the BPF filter
  itself (the flag is a register argument). Open mode does not
  support TCP fast open; programs fall back to a normal connect.
- D. io_uring is already denied; non-native ABIs are killed by the
  filter's foreign-architecture verdict and the x32 guard. There is
  no other entry path to the four operations that bypasses the
  filter.

**Supervisor-executed listen for every address family.** The
supervisor performs `listen` on its own reference for every address
family (INET and AF_UNIX), not just INET. The kernel never executes
a continued `listen` from a sandboxed task. The verdict table's
`Listen` entry is `SupervisorExecuted`; `KernelContinued` remains
only for `ConnectUnix` and `BindUnix` (AF_UNIX connect and bind),
which Landlock backs at kernel level.

**New kernel requirement.** Open mode requires Landlock ABI >= 4
(Linux 6.7). `hisn check` reports it; an open session on an older
kernel fails with a clear error, never silently.

**What is no longer supported.** TCP fast open in open mode.

**Peer-credential difference.** A client that reads `SO_PEERCRED`
on an AF_UNIX listener's accepted socket sees pid 0 (the supervisor
owns the listening socket, outside the sandbox pid namespace)
instead of the sandbox-internal pid. Uid and gid are unchanged.
See ADR 0022, "Amendment 0.6.2".

**Consequence.** With A–D in place and proven, the "open mode is for
trusted code" limitation of 0.6.1 is removed for the four operations
above.

## Known limitations

- **Non-blocking flag during connect:** the caller's `O_NONBLOCK`
  flag is briefly cleared and restored while the supervisor completes
  a blocking `connect`. The window is short (one `connect` syscall),
  but a signal arriving in that window sees a blocking socket.
- **Signal-interrupted calls:** a `connect` interrupted by a signal
  may be notified again by the kernel, resulting in a second
  notification for the same operation. The supervisor handles this
  by refusing the duplicate (`already-pending` or
  `already-connected`).
- **TCP fast-open:** `sendto`/`sendmsg` with `MSG_FASTOPEN` is
  refused with `EOPNOTSUPP` for every socket type (INET, AF_UNIX,
  any namespace). TCP fast-open is not supported in open mode.
