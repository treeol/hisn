# Release notes — hisn 0.6.5

0.6.5 makes external callers' lives easier: big requests and over-cap stdin
are reported instead of disappearing, `--no-tty` execs can opt in to a capped
stdin passthrough, and two new machine-readable commands answer "does this
host have X?" and "is my profile valid?". No wire change: protocol revision 4
stays, and the version existing commands declare stays 3, so a 0.6.4 or 0.6.3
client keeps working against a 0.6.5 supervisor and this CLI sends
byte-identical requests for every command that uses no new option.

## For callers

- **Oversized requests.** An `exec` request over 65536 bytes is refused before
  it is sent: exit 125 with a `hisn-error/v1` object (`E_TOO_LARGE`, naming
  the limit). Supervisor refusals reach the client as error replies, not
  closed connections.
- **Stdin for `--no-tty`.** `--stdin-limit BYTES` (opt-in) passes the caller's
  stdin through a capped relay. Without it, `--no-tty` keeps `/dev/null`.
  Over the cap: exit 125, `E_TOO_LARGE` naming the stdin limit; the journal
  records it; never silently truncated. `--seat-token-file -`: the cap counts
  only what follows the credential line. Detached execs keep `/dev/null`.
- **`hisn capabilities --json`.** `hisn-capabilities/v1`: version, protocol
  revision, declared protocol version, and 11 stable feature names
  (`detached-exec`, `journal-cursor`, `journal-unreadable`, `exec-stdin`,
  `seat-credential-stdin`, `network-none`, `network-host`, `network-open`,
  `rootfs`, `ssh-agent`, `services`) with `available` and a `reason` from the
  same checks `hisn check` runs when false. Works without a session.
- **`hisn profile validate --json`.** `hisn-profile-validation/v1`: `ok` and
  a fail-fast error list with the TOML key path, line and column when known,
  a stable code (`E_PROFILE_PARSE`, `E_PROFILE_VALUE`) and a message. Text
  output is unchanged.
- **Guide.** [docs/EXTERNAL-CALLERS.md](../EXTERNAL-CALLERS.md),
  [docs/CONTROL-PROTOCOL.md](../CONTROL-PROTOCOL.md).

## Fixed

- Log pruning no longer deletes files of an exec whose output pump is still
  running; a detached exec being written keeps its complete output.
- The name-registry check in the host scripts compares only entries of the
  script's own session prefix.
- `tests/leak/compat_063.sh` fails instead of passing when its live-session
  part is skipped.

## Known limits

- When the stdin cap is hit, the program sees EOF after the cap bytes and may
  commit before the client replaces its exit with 125.
- `capabilities` features derived from the binary (detached-exec, journal-*,
  exec-stdin, seat-credential-stdin, ssh-agent, services) report available
  even when a connected older supervisor would refuse them.
- `profile validate --json` is fail-fast: at most one error, the first one.
