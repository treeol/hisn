# Release notes — 0.6.7

0.6.6 was not released; 0.6.7 follows 0.6.5.

hisn 0.6.7 adds a blocking journal read for external callers and a
caller-provided ssh-agent socket. Nothing on the documented wire changes:
no new control request, `PROTOCOL_REVISION` stays 4, the declared protocol
version stays 3, and `tests/leak/compat_063.sh` passes unchanged — so
0.6.3 and 0.6.5 clients keep working against a 0.6.7 supervisor, and a
0.6.7 client against an older supervisor keeps today's refusals.

## Highlights

**`hisn journal --after-wseq N --wait [SECS]`** blocks until a record with
`wseq > N` exists, then prints it exactly like the non-wait path and exits
0. With `SECS` it gives up after that long and exits 6 (`E_WAIT_TIMEOUT`);
the session ending while waiting, with no matching records, exits 7
(`E_WAIT_SESSION_ENDED`). Exit 4 keeps meaning a real gap (reported
immediately, never waited on); exit 5 is left unused and documented as
such. Works with `--json` and `--session`. Wake is via inotify on the
journal file and directory with a bounded 1 s poll fallback when inotify
is unavailable. The wait holds no session lock and survives journal
rotation. A stop record with `wseq <= N`, a supervisor killed outright, or
a failed stop append cannot be detected from the journal alone — in those
cases the wait ends by its timeout.

**Caller-provided ssh-agent socket.** `hisn run --ssh-agent-socket PATH`
(mirrored as the profile `[ssh] socket` key, CLI winning) hands the
session's ssh-agent proxy a caller-chosen upstream instead of the host's
`SSH_AUTH_SOCK`. Default off; with neither set the upstream is
`SSH_AUTH_SOCK` exactly as before. The existing add/remove/lock refusal is
unchanged.

Every sign request now journals one `ssh/sign` record through the bounded
network queue: `fingerprint` (`SHA256:…` or null), `seat`, `attributed`,
`exec_id`, `result` (`ok`/`refused`/`error`). It never carries the data
being signed, the signature, or the key blob. Over-rate signs fold into
one `ssh/sign-summary` per affected second.

Attribution reuses the network records' `/proc` ancestry walk from the
accepted connection's peer pid (the proxy socket is a bind mount, so the
peer is the real in-sandbox client). The main command signs as owner,
owner/member execs sign, and an observer is refused with
`SSH_AGENT_FAILURE` and a `refused` record; an unattributed client
(orphan, reparented, unreadable) is also refused, marked
`attributed: false`. Note the documented pid-reuse limitation and that
identity listing stays ungated; a pidfd hardening is deferred (plan open
point P3).

**Capabilities.** `hisn capabilities --json` gains `journal-wait` and
`caller-agent-socket` after the existing 11 names, which are unchanged and
in the original order.

## Also in this release

- **C3 fixed:** a late `exec-signal` arriving while a detached exec drains
  could be missed by the journal cause. The cause is now finalised under
  the same `exec_table` lock the signal delivers through, so it cannot
  slip into the gap; a signal after a clean exit still cannot misclassify
  (the `exit` arm is unaffected).
- **C4 changed:** `hisn profile validate --json` reports all post-parse
  errors (deterministic, dedup'd order) instead of only the first. The text
  path stays fail-fast; `ok` and exit codes are unchanged. A TOML parse
  failure still stops with exactly one error.
- **Behaviour change:** the ssh-agent proxy now gates signs by seat role
  on both the env path and the caller-socket path (owner/member sign,
  observer refused). This reverses the old allowlist-only behaviour for
  observers.
- **Smaller:** `check_host_agent` error text names the path actually
  checked; `summary_for` has `ssh/sign` and `ssh/sign-summary` arms so
  readable `hisn journal` output never says "unrecognized ssh/sign".
- **Verified already fixed, dropped:** stale `prev_base` after a failed
  rotation (execlog), and `journal --info` trusting the index count (the
  index digest is checked; the count is not trusted).

## Verification

Unit tests, fmt, clippy, the leak suite, the net harness, `compat_063.sh`
and the release gate run on the test machine; `scripts/host-verify-0.6.7.sh`
carries the one-command check for your workstation.

## Deferred (open points)

CLI-only vs profile key for the agent socket (P1); gating identity listing
too (P2); pidfd attribution hardening (P3); ADR 0011/0021 amendments and
the "no follow mode" help text (P4); a cursor field in `--wait --json`
(P5); journaling refused non-sign agent messages (P6); exit code 5 stays
reserved (P7). See `docs/plans/0.6.7-wait-and-agent.md` §10.
